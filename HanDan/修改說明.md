# 菡萏咖啡存摺．待套用修改說明

本文件列出四項修改，套用對象為本機的 `菡萏咖啡-台股損益存摺.html`。
四項皆已在瀏覽器實測通過，可直接套用。

---

## 背景

原始 Excel 的「2026損益表」預先建好整年 52 列，但**最後一筆真實記錄是 2026-07-31**。
從 08-07 到 12-31 共 22 列，庫存與累計％完全相同，是把 07-31 的值往下複製的佔位列。

這造成兩個問題：

1. 圖表把佔位列當成真實資料，畫出一條延伸到年底的平線。
2. `syncedWeekly` 取「該年度最後一列」套用持股同步差額，寫到了 12-31 而非當週，
   使 12-31 出現 -10.21% 這種不存在的週績效。

---

## 修改一：新增 todayISO 函式

**位置**：`combinedWeekly` 函式的正上方。

**動作**：新增以下函式。

```javascript
function todayISO() {
  const d = new Date();
  const p = n => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${p(d.getMonth() + 1)}-${p(d.getDate())}`;
}
```

## 修改二：combinedWeekly 濾除未來週次

**位置**：現有的 `combinedWeekly` 函式。

**動作**：整個函式以下列內容取代。

```javascript
function combinedWeekly(acc, year) {
  const base = (PORTFOLIO_DATA.weekly[acc] && PORTFOLIO_DATA.weekly[acc][year]) ? PORTFOLIO_DATA.weekly[acc][year].map(e => ({...e, custom:false})) : [];
  const custom = (state.customWeekly[acc][year] || []).map(e => ({...e, custom:true}));
  const all = [...base, ...custom].sort((a,b) => a.date.localeCompare(b.date));

  // 原始 Excel 預先建好整年 52 列，尚未到來的週次是把最後一筆真實記錄
  // 往下複製的佔位列。這些不是實際觀測值，畫出來會變成延伸到年底的平線，
  // 也會讓持股同步寫到錯誤的列，故一律排除。
  const today = todayISO();
  return all.filter(r => r.date <= today);
}
```

**效果**：2026 年的週資料從 52 筆降為 30 筆，末筆為當前這一週。
過往年度所有列都在今天之前，不受影響。

## 修改三：syncedWeekly 年度比對加固

**位置**：`syncedWeekly` 函式內。

**找到這一行**：

```javascript
  if (year !== latestYear) return data;
```

**取代為**：

```javascript
  // 年度值在不同呼叫端可能為字串或數字，統一轉型後比對，
  // 否則嚴格比對會讓同步靜默失效。
  if (Number(year) !== latestYear) return data;
```

**理由**：`latestYear` 恆為數字。若 `year` 以字串傳入，嚴格比對必然成立而直接跳過同步，
且不會有任何錯誤訊息。目前呼叫端傳的都是數字，此項屬預防性處理。

## 修改四：週績效柱狀圖

**位置**：現有的 `renderWeeklyChart` 函式。

**動作**：整個函式以下列內容取代。

```javascript
function renderWeeklyChart() {
  if (!chartsAvailable()) return;
  const data = syncedWeekly(state.account, state.weeklyYear);
  const labels = data.map(d => d.date.slice(5));
  const inv = data.map(d => d.inventory);
  const cum = data.map(d => d.cum_pct * 100);

  // 週績效 = 本週累計績效 − 上週累計績效。
  // 以累計值相減即時計算，不直接讀取原始欄位，
  // 這樣手動新增或同步持股明細後的資料點也能維持一致。
  const wow = data.map((d, i) => {
    if (i === 0) {
      // 首週無前一週可比，沿用原始資料的週績效欄位。
      return d.wow_pct != null ? d.wow_pct * 100 : null;
    }
    const prev = data[i - 1].cum_pct;
    if (d.cum_pct == null || prev == null) return null;
    return (d.cum_pct - prev) * 100;
  });
  const wowColors = wow.map(v => v == null ? 'rgba(0,0,0,0)'
    : (v >= 0 ? 'rgba(194,59,59,0.55)' : 'rgba(47,125,92,0.55)'));

  const pointColors = data.map(d => d.holdingsSynced ? '#2f7d5c' : (d.custom ? '#c9a02b' : '#22314f'));
  const pointRadius = data.map(d => (d.custom || d.holdingsSynced) ? 5 : 2);
  const ctx = document.getElementById('weeklyChart').getContext('2d');
  if (weeklyChartInstance) weeklyChartInstance.destroy();
  weeklyChartInstance = new Chart(ctx, {
    data: {
      labels,
      datasets: [
        {
          type: 'bar', label: '週績效 %', data: wow,
          backgroundColor: wowColors, borderWidth: 0,
          yAxisID: 'y1', order: 3,
        },
        {
          type: 'line', label: '庫存市值', data: inv,
          borderColor: '#1e3358', backgroundColor: 'rgba(30,51,88,0.08)',
          fill: true, tension: 0.25, yAxisID: 'y', order: 1,
          pointBackgroundColor: pointColors, pointRadius,
        },
        {
          type: 'line', label: '累計績效 %', data: cum,
          borderColor: '#c23b3b', borderDash: [4,3], tension: 0.25,
          yAxisID: 'y1', pointRadius: 0, order: 2,
        }
      ]
    },
    options: {
      responsive: true,
      plugins: {
        legend: { labels: { color:'#22314f' } },
        tooltip: {
          callbacks: {
            label: (c) => {
              const v = c.parsed.y;
              if (c.dataset.label === '庫存市值') return `庫存市值：${fmtMoney(v)}`;
              if (v == null) return `${c.dataset.label}：—`;
              return `${c.dataset.label}：${v >= 0 ? '+' : ''}${v.toFixed(2)}%`;
            },
            afterLabel: (c) => c.dataset.label === '庫存市值'
              ? (data[c.dataIndex].holdingsSynced ? '（已同步持股明細的修改）'
                : (data[c.dataIndex].custom ? '（手動新增）' : ''))
              : ''
          }
        }
      },
      scales: {
        x: { ticks: { color:'#5b6785', maxRotation:0, autoSkip:true, maxTicksLimit:14 }, grid:{display:false} },
        y: { position:'left', ticks:{ color:'#5b6785', callback:v=>(v/10000)+'萬'}, grid:{ color:'rgba(228,220,198,0.6)' } },
        y1:{ position:'right', ticks:{ color:'#c23b3b', callback:v=>v+'%'}, grid:{display:false} },
      }
    }
  });
}
```

### 計算規則

週績效 = 本週累計績效 − 上週累計績效。

採即時計算而非讀取原始 `wow_pct` 欄位，使手動記帳或同步持股後新增的資料點
也依同一規則計算，避免新舊資料規則不一。首週無前一週可比，沿用原始欄位值。

### 規則驗證

以原始資料全量比對「累計差」與 Excel 的 `wow_pct` 欄位，**427 筆中 425 筆吻合**。

兩筆不符為原始檔的儲存格參照錯誤：

| 日期 | Excel 值 | 實際參照 | 依規則應為 |
|---|---|---|---|
| 2025-12-26 | +1.614% | 累計(12-26) − 累計(**12-12**) | +0.880% |
| 2025-12-31 | +2.030% | 累計(12-31) − 累計(**12-19**) | +1.150% |

兩筆都跳過了前一週，且該期間成本無變動，可排除加減碼因素。
推測是年底插入 12-31 這一列時參照位移所致。**本修改採規則計算值，不沿用這兩個錯誤數字。**

### 視覺設計

紅柱為正、綠柱為負，與全站損益配色一致。柱狀與累計績效**共用同一個百分比座標軸**。

此處有一項取捨：2025 年累計績效跨度達 −25% 至 −6%，共用座標軸時 ±3% 的柱狀會被壓縮。
若改用獨立座標軸放大柱狀，視覺上會讓單週波動看起來與整年跌幅相當，反而失真。
目前呈現雖然柱狀較小，但比例真實。

## 套用後的驗證方式

1. 開啟網頁，切到「01 總覽與趨勢」。
2. 年度選 2026，確認圖表**末點為 07-31**，不再延伸到 12-31。
3. 圖例應出現三項：庫存市值、累計績效 %、週績效 %。
4. 前五週的週績效應為：`+0.88%  +1.69%  +3.00%  -1.14%  -2.11%`。
5. 到「02 持股明細」按「取得盤後收盤價」，回到總覽，
   確認同步後的變動落在 **07-31** 那一根柱子上。

## 一項待你確認的設計決定

濾除未來週次後，圖表只畫到本週。

若你原本是刻意保留那些佔位列作為視覺參考，此改動會與你的預期不符。
替代做法是保留佔位列但以虛線淡色呈現，明確區分「已記錄」與「未來待填」，而非直接隱藏。
